`mmvmiaojianbrokersvr` 是跑在网关层的中转服务，只有 10 个接口。它的职责是**把秒剪侧的编辑元数据与视频号侧的视频对象关联起来**，以及承载一小部分需要按平台分发的运营配置。

关联的主键是**视频文件的 MD5**：秒剪在导出时把这次编辑的元数据（用了什么模板、什么音乐、素材有多少段、打了哪些标签）以 MD5 为键存下来；视频号侧拿到视频后，用同一个 MD5 反查这些元数据。

这个设计的前提是文件指纹在两侧一致——同一个视频文件在秒剪导出和视频号入库后 MD5 不变。

## 核心流程

### 以 MD5 为桥的两段写入与读取

写入侧是秒剪：`AddVideoMeta` 把 MD5、用户标识、时间戳和一段扩展信息存下来。扩展信息是一个 JSON 字符串，里面是这次编辑的完整上下文。

读取侧有两个方向：

```text
秒剪侧：按 MD5 查元数据（单条或批量）→ 取出扩展信息 → 展开成结构化字段
视频号侧：按 MD5 反查视频号对象 → 拿到 objectId、作者、模板 ID
```

`ValidateVideo` 只回答"这个 MD5 有没有记录"，是一个轻量的存在性判断，用于避免为不存在的视频走完整查询。

扩展信息的内容随业务演进不断变长：从最早的项目 ID、时长，到后来的场景标签、音频标签、V4 版标签体系、音色列表。它是一个**不断追加字段的 JSON**，解析侧按字段取，缺失即为零值。

### 评论区跳转配置的三级回退

视频号评论区要展示"用同款模板剪一个"的入口，入口的图标和文案由本服务下发。配置不是写死的，按三级优先级回退：

```text
1. 创作模式有值且在配置表里命中 → 用创作模式对应的图标文案
2. 模板 ID 非空且不是"无模板"     → 用模板对应的图标文案
3. 音乐 Key 非空                  → 用音乐对应的图标文案
4. 都不满足                        → 用默认图标文案
```

这个顺序是有语义的：创作模式（剪同款、图文等）是最强的信号，其次是具体模板，再次是音乐，最后才是兜底。用户从哪个维度进来的，入口就强调哪个维度。

配置本身按平台分开：Android 与鸿蒙共用一份，iOS 一份。鸿蒙复用 Android 配置是过渡期的做法——两者当时的客户端能力一致，单独维护一份配置没有收益。

配置从云控读取，配置为空时直接返回空响应而不是报错：评论区入口是增强能力，没有它评论区照常显示。

### 解绑模板关联时的双路径

视频被判定为不合规时，要解绑它与模板的关联。这里分两种情况：

```text
视频正常   → 只上报数据
识别不成功 → 调视频号接口解绑 + 上报
```

区别在于"识别不成功"意味着模板识别本身出了问题，光在秒剪侧记录不够，还要让视频号侧真正解除绑定关系。这时要走一次 mesh 调用：申请服务票据、发起解绑 RPC、校验返回码。

两种情况都要上报数据，上报内容里带一个标志位区分是哪条路径，便于后续统计识别失败率。

## 设计与取舍

**用文件 MD5 而不是业务 ID 做关联。** 秒剪导出和视频号入库是两个独立流程，没有共享的业务 ID；文件指纹是唯一天然一致的键。代价是同一段素材被导出两次会产生两条记录，且 MD5 冲突（虽然概率极低）会导致串数据。

**扩展信息用不断追加的 JSON。** 新增字段不需要改表结构，老记录缺字段时按零值处理。代价是这个 JSON 会持续膨胀，且没有版本概念——字段含义变化只能靠新增字段而不是修改。

**配置下发按平台分文件，鸿蒙复用 Android。** 减少一份需要维护的配置。代价是鸿蒙客户端能力独立演进后需要拆分，届时改动涉及配置结构与读取逻辑。

**配置缺失时返回空而不是报错。** 评论区入口是增强，缺失不应影响评论区本身。代价是配置错误（比如 JSON 结构写错）和配置未配的表现一样，排查时不好区分。

**解绑分双路径，只有识别失败才调视频号。** 正常情况只在秒剪侧记录，避免每次解绑都要一次跨系统 RPC。代价是两条路径的上报格式要保持一致，否则统计口径会乱。

## 后续优化方向

**扩展信息 JSON 没有版本与校验。** 字段只增不改，含义变化靠新增字段规避，长期会积累语义相近的重复字段（V4 标签与旧标签并存就是例子）。可以引入版本号与字段生命周期管理。

**MD5 关联没有冲突处理。** 理论上不同文件可能算出相同 MD5，当前没有冲突检测或二次校验，冲突会表现为元数据串台。

**鸿蒙复用 Android 配置是临时状态。** 两端能力一旦分化，这份复用就要拆开，且拆分涉及配置键的重新组织。

**平台判断散落在业务逻辑里。** 评论区配置的函数内直接用字符串比较判断平台，新增平台要改多处分支，而不是查一张平台能力表。

**云控配置读取没有本地缓存。** 每次请求都读云控，配置量大或服务调用频繁时会成为瓶颈；且云控不可用时的降级行为不明确。

## 外部依赖与系统边界

- **视频号侧提供视频对象查询与模板解绑接口**，本服务通过 mesh 调用，需要申请服务票据，其可用性与限流策略决定了这些接口的成败
- **云控配置系统承载评论区入口的图标文案配置**，配置的更新时机与结构正确性由运营侧保证，本服务只读取并解析
- **文件 MD5 由秒剪客户端在导出时计算并上传**，指纹算法与上传时机由客户端决定，本服务只做存储与反查
- **数据上报通道由内部的 mmdata 服务提供**，解绑与识别结果的统计数据经此上报，上报失败不影响主流程
- **模板识别能力在视频号侧**，识别失败率是本服务"识别不成功"分支的触发条件，其准确率决定了这条路径的触发频率
