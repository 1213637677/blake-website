# Blake 个人网站 · 产品需求文档

版本 v1.0 · 2026-10-10

## 1. 背景与目标

一个长期维护的个人站点，用来沉淀三类内容：

1. **工作项目经历**：做过的项目、负责的模块、技术选型与结果。
2. **个人感悟与学习经历**：读书、踩坑、方法论、阶段性复盘。
3. **自己做的项目**：独立/业余项目，含演示与源码链接。

核心目标：

- **写得下去**：写作摩擦要低，十年后还能维护，不依赖任何会倒闭的 SaaS。
- **读得舒服**：首页就能看到"最近在做什么"，文章页专注阅读。
- **有自己的样子**：不是模板站，不是清一色的渐变卡片堆。

非目标：不做评论系统（可后续接 Giscus）、不做多用户、不做付费/订阅、不做复杂的 CMS 权限体系。

## 2. 用户与场景

| 角色 | 场景 | 关键诉求 |
| --- | --- | --- |
| 本人（作者） | 周更/月更地记录项目与学习 | 写完即发布，格式简单，支持草稿 |
| 本人（作者） | 临时在 iPad/手机上补一条笔记 | 浏览器里就能编辑，不用开电脑 |
| 访客（同行/招聘方） | 想快速了解这个人做过什么 | 首页 10 秒内看到项目与近期动态 |
| 访客 | 被某篇文章吸引，想深入读 | 干净的排版、可搜索、可订阅 RSS |

## 3. 信息架构

```
/                     首页：身份介绍 + 当前在做的事 + 混合时间线 + 精选项目
/projects             项目（工作项目 / 个人项目，可筛选）
/projects/[slug]      项目详情：背景、我的角色、技术栈、结果、链接
/writing              博客文章（感悟、学习、复盘），支持标签筛选
/writing/[slug]       文章详情：阅读时间、标签、上下篇
/notes                短笔记流：一句话到几百字的轻量记录
/tags                 标签总览
/tags/[tag]           单标签聚合（跨文章/项目/笔记）
/search               全文搜索（客户端索引，零后端）
/about                关于我 + 联系方式 + 简历入口
/feed.xml             RSS
/admin                后台：登录、新建/编辑/删除、草稿态、图片上传
```

内容模型统一为"条目（entry）"，三类共用同一套字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string | 标题 |
| `summary` | string | 一句话摘要，用于卡片与 SEO |
| `date` | date | 发布日期 |
| `updated` | date? | 最后更新 |
| `tags` | string[] | 标签 |
| `draft` | boolean | 草稿，生产环境不可见 |
| `pinned` | boolean | 首页/列表置顶 |
| `cover` | string? | 封面图 |
| `kind` | enum | `work` / `personal`（仅项目） |
| `role`, `stack`, `links` | 项目专属 | 角色、技术栈、外链 |

## 4. 写作与发布流程（关键设计）

这是全站最重要的决策。方案对比：

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 数据库 + 传统 CMS（WordPress 类） | 可视化 | 要运维数据库、备份、迁移成本高 | ❌ 重 |
| 第三方 Headless CMS（Contentful / Notion API 等） | 编辑体验好 | 绑定厂商，账号/计费/API 变更会拖垮站点 | ❌ 不可长期依赖 |
| **Git 仓库里的 Markdown/MDX**（业界主流） | 纯文本、可 diff、可迁移、离线可写、免费托管 | 需要一点 Git 习惯 | ✅ **作为唯一数据源** |
| **自建轻量 Admin**（`/admin`） | 浏览器里写，手机/平板也能发，数据与仓库同源 | 需要一次简单的身份认证 | ✅ **作为编辑入口** |

最终方案：**"仓库即数据库 + 自带后台"双通道**。

- **唯一数据源**：`content/` 下的 `.md`/`.mdx` 文件（frontmatter + 正文）。任何时刻删掉后台，站点照常构建。
- **通道 A（主力）**：本地编辑器写 Markdown → `git commit && git push` → 自动部署。
- **通道 B（补充）**：`/admin` 登录后在浏览器写，后台直接把文件写回 `content/`，支持保存草稿、预览、图片上传；写完推一次 Git 即固化。
- **认证**：单用户口令登录（`ADMIN_PASSWORD` 环境变量），HttpOnly + SameSite 签名 Cookie，服务端路由全部校验；未配置口令时后台自动禁用。
- **部署**：静态构建（Vercel / Netlify / Cloudflare Pages / GitHub Pages 均可），`/admin` 只在本地或自托管 Node 下启用。

这样既满足"admin 账号"的诉求，又比"自建数据库后台"更主流、更抗风险。

## 5. UI 设计

### 5.1 设计定位

**"工程师的工作手记（Lab Notebook）"** —— 编辑排版优先，信息密度高，克制但有几处记忆点。

不是营销落地页，不做大 Hero 卡片堆砌；不是开发者模板站的紫蓝渐变。整体气质接近一份排版讲究的技术期刊：留白充足、网格严谨、细节处有手工感。

### 5.2 视觉规范

- **配色**（浅色为主，深色为对等的一等公民，不是反色凑数）
  - 底色 `--paper: #F6F7F5`（冷调纸白，避免米黄）、`--paper-2: #FFFFFF`
  - 墨色 `--ink: #15181B`、`--ink-2: #4A5158`（正文/次要）
  - 主强调 `--accent: #1F6B54`（松墨绿，用于链接、选中态、强调线）
  - 次强调 `--signal: #B4531B`（赭石，仅用于标签、时间线节点、小面积高亮）
  - 分隔线 `--rule: #E2E5E1`
  - 深色模式：`--paper: #0F1211`、`--ink: #E7EAE6`，强调色提亮一档
  - 强调色总占比控制在 5% 以内，靠留白与字重分层，不靠色块
- **字体**
  - 正文/标题：`"Inter", system-ui` + 中文回退 `"PingFang SC", "Noto Sans SC"`（自托管子集化字体，避免 FOUT 与第三方请求）
  - 元数据、`日期 / 标签 / 技术栈 / 编号`：`"JetBrains Mono", ui-monospace`，小字号 + 大写字距，形成"手记"的工业感
  - 正文 17–18px，行高 1.75，中文行高略放宽；标题用 `clamp()` 阶梯，不用 vw 缩放
- **网格与尺度**
  - 12 栏栅格，内容容器最宽 1080px；正文栏 68–72 字符（约 680px）
  - 卡片圆角 ≤ 8px，靠 1px 描边与留白分区，不用阴影堆叠
  - 8px 间距体系
- **组件约定**
  - 图标统一 lucide（内联 SVG），图标按钮带 tooltip/aria-label
  - 开关用 toggle/checkbox，选项集合用 menu/segmented，数值用 stepper，视图切换用 tabs
  - 按钮为文字或图标+文字；不以圆角方块加文字代替符号

### 5.3 页面设计要点

**首页**
1. 顶部细导航：站点名（`Blake`）+ 五个入口 + 主题切换 + 搜索图标，滚动后变窄并加细边。
2. 首屏：左侧大幅姓名/一句话定位 + 当前状态（如"在做什么"），右侧是**实时状态卡**：最近提交的一条笔记、正在做的项目、更新时间。不用营销大图。
3. **混合时间线**（本站的记忆点）：把文章、项目、笔记按时间混排成一条垂直年表，每条左侧是等宽字体的日期与类型标记（`LOG / POST / PROJECT`），右侧是标题与摘要；年份作为分隔标题，hover 时整行左侧出现 2px 墨绿竖线。时间线可切换筛选（全部 / 文章 / 项目 / 笔记）。
4. 精选项目区：3 张紧凑卡片，只有标题、一句话、技术栈、外链箭头。
5. 页脚：RSS、源码、邮箱、版权，极简。

**列表页（`/writing`、`/projects`、`/notes`）**
- 顶部一行筛选：标签 chip + 关键词输入 + 排序（新→旧）。
- 项目页用双态 segmented 切换「工作 / 个人」。
- 空结果有明确的空状态文案。

**详情页**
- 标题上方是面包屑式的元信息行：`2026.10.10 · 阅读 6 分钟 · #标签`。
- 正文排版：段落间距、引用左侧竖线、代码带语言标签与复制按钮、图片带说明、脚注。
- 文末：上下篇导航 + 返回顶部。
- 项目详情另含：背景 / 我的角色 / 技术栈 / 结果与反思 / 外链（Demo、源码、文章）。

**后台 `/admin`**
- 登录：单口令，居中窄卡片。
- 列表：所有条目表格（类型、标题、状态、更新日期），右侧操作图标。
- 编辑器：标题/摘要/日期/标签/草稿开关在左，Markdown 正文在右，实时预览可切换；保存即写回仓库文件。

### 5.4 响应式与可访问性

- 断点：`<640`（单列，导航收起为顶栏 + 底部快捷入口）、`640–1024`、`>1024`。
- 所有交互元素 ≥ 44px 触控区；焦点可见；`prefers-reduced-motion` 下关闭过渡。
- 主题跟随系统，可手动覆盖并记忆（`localStorage`），首屏内联脚本避免闪白。
- 对比度 AA 以上，图标按钮皆有可读名称。

## 6. 功能清单

### P0（本次交付）
- 首页：身份区 + 状态卡 + 混合时间线（含筛选）+ 精选项目
- 文章 / 项目 / 笔记：列表（标签筛选 + 关键词）+ 详情
- 标签总览与标签聚合页
- 客户端全文搜索（构建期生成 JSON 索引，纯前端匹配，带高亮）
- 深色/浅色主题切换 + 记忆
- RSS 2.0、sitemap、robots、OG/Twitter meta
- `/admin`：口令登录、列表、新建、编辑（Markdown + frontmatter）、删除、草稿态、上传图片
- 站点配置集中化（站点名、简介、社交链接、导航），改一处即可
- 404 页

### P1（后续）
- 评论（Giscus）、阅读进度、目录（TOC）、OG 图自动生成
- 项目数据统计（GitHub API 拉取 star 等）
- 后台支持 MDX 组件、拖拽上传图片、自动提交 Git

## 7. 技术方案

- **框架**：Astro 5（内容集合 content collections + 类型安全 frontmatter），公共页面静态预渲染，后台走 Node 适配器
- **内容**：`.md`/`.mdx` + Zod schema 校验，构建期报错，不静默
- **样式**：原生 CSS（设计 token + 少量 utility），不引入 CSS 框架，保证设计不被框架默认样式稀释
- **搜索**：构建期生成 `search-index.json`，前端模糊匹配 + 高亮
- **后台**：Astro 服务端路由 + Cookie 会话（HMAC 签名），文件读写限 `content/` 与 `public/uploads/`
- **部署**：静态产物可直接托管任意 CDN；后台需 Node 运行时，本地或自托管使用

## 8. 内容策略（初始留空说明）

本次交付内容与链接先留空，仅保留：

- 1 篇占位文章、1 个占位项目、1 条占位笔记（用于验证渲染与样式，可随时删除）
- 站点配置中的姓名、简介、邮箱等字段留待填写（集中在 `src/config.ts`）

建议的更新节奏：工作项目在结项时补一篇；学习类每周一条笔记；感悟类随手写草稿，想清楚再发。

## 9. 验收标准

1. `npm run build` 通过，无类型与 schema 错误。
2. 首页、三大列表页、详情页、标签页、搜索页、`/admin` 在桌面与移动端均可访问且无重叠/溢出。
3. 深色模式在每个页面表现一致。
4. 后台可完成"登录 → 新建 → 保存 → 列表中可见 → 详情页可见"闭环。
5. RSS 可被阅读器解析，sitemap 包含全部公开页面。
