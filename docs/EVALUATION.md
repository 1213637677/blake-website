# 产品文档评估（第 2 步）

评估对象：`docs/PRD.md` v1.0

## 结论

**可行**。范围与主流个人站一致，无技术上不可实现项；方案取舍偏保守但正确。以下列出评估中发现的问题与本轮已做的修正。

## A. 与主流个人站设计的对齐度

| 主流做法 | 本方案 | 判定 |
| --- | --- | --- |
| 静态站生成 + Markdown 内容源（Astro / Hugo / Jekyll / Next MDX） | Astro + content collections | ✅ 对齐，已是最主流组合 |
| 内容放 Git，部署接 CDN | 同 | ✅ |
| 自建后台或接 Headless CMS | 自建极简后台 + 仓库为唯一数据源 | ✅ 兼顾，且规避了厂商绑定 |
| RSS、sitemap、OG 卡片、深色模式 | 全部包含 | ✅ |
| 站点搜索 | 构建期索引 + 前端匹配（Pagefind 同类思路） | ✅ 无后端，成本最低 |
| 排版优先、克制配色、等宽字做元信息 | 同 | ✅ 与优秀工程博客一致 |

**未对齐/需留意的点**（已处理或已降级）：

1. **评论系统**主流做法是 Giscus/utterances。PRD 已列入 P1，不在首版，合理——首版应避免引入第三方登录依赖。
2. **TOC 与阅读进度**在中长文里几乎是标配。本轮作为 P1，但详情页已预留位置，后续加上不改动结构。
3. **内容量极少时的"空站"观感**：主流做法是先做足内容再上线。本方案用占位内容保证渲染可验证，同时在首页明确"内容与链接待填"，可接受。

## B. 方案自身的风险与修正

1. **后台写文件与 Git 工作流冲突（中风险）**
   浏览器写入的是部署所在机器的 `content/`，若部署平台是只读或按构建快照运行（Vercel/Netlify 常见），写入会丢失。
   → **修正**：把 `/admin` 明确定位为"本地 / 自托管 Node 运行时"下的编辑通道；静态托管时后台自动禁用并给出说明。不把它当作线上 CMS 承诺。

2. **单口令认证的安全性边界（中风险）**
   单口令只防随手访问，不耐暴力破解。
   → **修正**：口令走环境变量、未设置则后台禁用；会话 Cookie 做 HMAC 签名 + HttpOnly + SameSite=Lax；登录失败加固定延迟与限流计数；管理路由全部服务端校验，不依赖前端隐藏。

3. **路径穿越与写入越权（高风险，必须防）**
   后台读写文件名来自用户输入。
   → **修正**：slug 强制正则白名单（`^[a-z0-9][a-z0-9-]*$`），解析后校验真实路径必须落在 `content/` 或 `public/uploads/` 内；上传限制类型与体积。

4. **中文搜索体验（中风险）**
   纯空格分词对中文无效。
   → **修正**：中文按字符 bigram 切分建索引，匹配后按命中片段高亮；索引体积可控（先做标题+摘要+正文前若干字符）。

5. **字体加载与 FOUT（低风险）**
   依赖 Google Fonts 会在国内环境慢或失败。
   → **修正**：不引第三方字体 CDN，用系统字体栈（西文 Inter→system-ui，中文 PingFang SC / Noto Sans SC 回退），等宽用 ui-monospace 栈。牺牲一点字体独特性，换取首屏稳定。

6. **"十年后还能维护"的宣示需要约束**
   → **修正**：尽量少依赖；样式用原生 CSS 而非框架；后台可整体删除而站点照常构建（后台依赖与内容管线解耦）。

## C. 独特设计思路（这部分站得住）

1. **混合时间线（Mixed Timeline）**：文章、项目、笔记按时间混排成一条年表，用 `LOG / POST / PROJECT` 的类型标记区分。这是全站记忆点，也最符合"记录经历"的原始诉求——它呈现的是"这段时间我在做什么"，而不是"这是博客/这是作品集"的分类思维。
2. **首页实时状态卡**：一句话"现在在做什么"+ 最近一条笔记 + 正在做的项目，回答访客的第一疑问，替代常规的大头照 + 自我介绍。
3. **纸白 + 墨绿 + 赭石**：冷调纸白底、墨绿作主强调、赭石只用于小面积节点。避开当下模板站常见的紫蓝渐变与米黄奶油色，接近技术手记/期刊的质感。
4. **等宽字体承载元信息**：日期、编号、技术栈用小号等宽字 + 大写字距，与正文衬线感形成对比，成本低但辨识度高。
5. **后台与仓库同源**：不是"另一个 CMS"，只是给同一批 Markdown 文件加了一个浏览器入口，随时可以弃用。

## D. 范围裁决

砍掉（避免过度设计）：评论系统、自动 OG 图、GitHub star 拉取、MDX 复杂组件、多语言、邮件订阅。
保留但延后：TOC、阅读进度、Giscus。
